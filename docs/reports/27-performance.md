# گام ۲۷ — عملکرد

مرجع: Addendum §۱–۱۹، §۹۱–۹۵ · §۶۸، §۸۳–۸۵، §۱۳، §۱۹۱ · PART 102

بیکن سنجش میدانی، اندازه‌گیری سمت سرور، عبور از بودجه، و خط لولهٔ تصویر (AVIF/WebP).
یک اصل: **بایتِ سروشده را می‌سنجیم، نه اندازهٔ فایل را.** چهار باگ واقعی از همین تفاوت درآمد؛ هر چهار
تا پیش از این گام سبز بودند.

نقص ۱ و ۲ هر دو یک الگو دارند: **«کار می‌کند» به‌جای «اندازه‌گیری شد»**. آزمونِ جدید، بایتِ سروشده را با
دیسک مقایسه می‌کند و ثبتِ نمونه را در جدول می‌خواند.

## بیکن سنجش میدانی (`apps/web/assets/vitals.js`)

LCP، INP، CLS، TTFB، FCP — با `PerformanceObserver`، بی‌کتابخانه، ~۴KB خام.

- **داده‌محور:** نرخ نمونه‌گیری از `rum_sample_rate` **بودجهٔ همان مسیر** می‌آید و در `<meta name="pv-rum">` چاپ
  می‌شود؛ مسیر بی‌بودجه یا با نرخ ۰ (مثل ورود) هیچ نشانه‌ای ندارد.
- **حریم خصوصی:** بی‌کوکی، بی‌ذخیره‌سازی، بی‌شناسه؛ فقط `location.pathname` (پرس‌وجو و لنگر می‌توانند توکن
  داشته باشند)؛ «ردیابی نکن» محترم است. آزمون، الگوهای ممنوع را در متن اسکریپت جست‌وجو می‌کند.
- **CLS** بدترین «پنجرهٔ نشست» (تعریف رسمی)، **INP** کندترین تعامل (یا صدک ۹۸ برای بیش از ۵۰ تعامل).
- ارسال **یک‌بار** هنگام پنهان‌شدن صفحه (`sendBeacon`)، حداکثر ۵ نمونه.
- CSP دست‌نخورده: اسکریپت هم‌مبدأ، `defer`، با درهم محتوا؛ **هیچ اسکریپت درون‌خطی** نیست.

آزمون، خودِ فایل را در یک جعبهٔ `vm` اجرا می‌کند (بی‌مرورگر ولی همان کد): نمونه‌گیری، DNT، CLS، INP، شکل بار.

## رلهٔ فهرست‌سفید به API (`apps/web/src/proxy.ts`)

مرورگر فقط با مبدأ صفحه حرف می‌زند (`connect-src 'self'`). بیکن باید زیر مبدأ سایت به API برسد. رله **هیچ
منطقی ندارد**؛ فقط عبور، با فهرست سفید: `(سایت، متد، مسیر)` — اکنون **یک** قاعده: `POST /api/v1/public/vitals`
روی سایت عمومی، JSON/`text/plain`، حداکثر ۱۶KB، بی‌کوکی.

| اصل | چرا |
| --- | --- |
| فهرست سفید بسته | هر چیز دیگر همان ۴۰۵ همیشگی؛ وجود یک مسیر API اوراکل نمی‌سازد |
| سقف بدنه، ۴۱۳ **پیش** از قطع اتصال | قطع پیش از پاسخ، کلاینت را با `ECONNRESET` رها می‌کند |
| `X-Forwarded-For` از سوکت، نه کلاینت | وگرنه هر کسی IP جعلی می‌ساخت و محدودیت نرخ چهاربُعدی (§13) دور زده می‌شد |
| `X-Forwarded-Proto` از پیکربندی | ادعای کلاینت اعتماد نمی‌شود |
| کوکی/`Authorization` به API نمی‌رسد؛ `Set-Cookie`/`Server` برنمی‌گردد | مسیر بی‌نام است |
| شکست API ⇒ ۵۰۲/۵۰۴ ثابت | بی‌جزئیات داخلی |

نکتهٔ استقرار: با این رله، API باید `TRUST_PROXY=true` داشته باشد؛ وگرنه همه از یک IP دیده می‌شوند. در استقرار با
پروکسی (nginx) همین کار را پروکسی می‌کند. پنل‌ها (گام ۲۸–۳۰) قاعدهٔ خودشان را همین‌جا می‌گیرند.

## اندازه‌گیری و عبور از بودجه

`apps/web/src/measure.ts` + `npm run perf:budget` (یا `-- --json`، `--per-pattern N`):

- از `/sitemap.xml` شروع می‌کند، نشانی‌ها را **بر اساس الگوی بودجه** گروه می‌کند، از هر گروه نمونه می‌گیرد؛
- هر صفحه را با همهٔ منابع نخستین‌نما رندر می‌کند: HTML، CSS، JS (brotli)، فونتِ واقعاً بارشده، تصویرِ غیرتنبل؛
- هر اندازه‌گیری را با `ops.check_budget` می‌سنجد؛ کد خروج ۱ برای `fail`، `unbudgeted` یا منبع ۴xx/۵xx.

**بودجهٔ منبع‌به‌منبع** (Addendum §۱–۴؛ مهاجرت `0022`، seed `0007`): `html_kb`، `css_kb`، `js_kb`، `image_kb`،
`font_kb`. `js_kb = 0` معنای روشن دارد («بدون JavaScript»). عددها از **اندازه‌گیری** آمده‌اند.

اندازه‌گیری امروز (فشردهٔ brotli، خروجی `npm run perf:budget`): HTML ۱٫۶–۲٫۹ KB، CSS ۸٫۳ KB، فونت ۸۱٫۱ KB
(= ۸۳٬۰۴۸ بایت)، JS ۱٫۷ KB (بیکن)، **جمع نخستین‌نما ۹۳–۹۵ KB در ۵ درخواست**، برای همهٔ الگوهای عمومی.

**صادق:** LCP/INP/CLS بدون مرورگر ممکن نیست؛ در `not_compared` می‌مانند و جایشان RUM (بیکن) است. «قبول» اینجا
یعنی «در سنجه‌های سروشده تخطی نیست»، نه «سریع است».

## خط لولهٔ تصویر (AVIF/WebP)

`apps/web/src/imagepipeline.ts`. `sharp` (libvips ۸٫۱۷) **وابستگیِ اختیاری** است.

- **وضعیت صریح** (PART 102): `configured` (با نسخهٔ libvips) یا `not_configured` با دلیل. بی‌موتور، سایت کار می‌کند:
  `<img>` ساده، بی‌`<picture>`، و هیچ نشانیِ ناسروشدنی‌ای چاپ نمی‌شود.
- **نشانی تغییرناپذیر و بسته:** `/media/<شناسه>?w=<عرض>&f=<قالب>&v=<درهم>`. عرض از نردبان تنظیمات (`platform.image_pipeline`،
  داده) یا خودِ عرض اصلی؛ هرگز بزرگ‌تر از اصل، هرگز بیش از ۷ گزینه. قالب از فهرست. `v` پیشوند درهم فایل است، پس
  `immutable` همیشه امن است. **«تقریباً درست» وجود ندارد:** `w=641` ⇒ ۴۰۴. نردبان بسته یعنی تعداد نسخه‌ها متناهی است؛
  وگرنه هر `?w=` یک تبدیل و یک فایل می‌ساخت.
- **انبار دیسک محتوامحور** (کلید = درهم، نه نامی از درخواست؛ پیمایش مسیر ساختاراً ممکن نیست)، نوشتن اتمی،
  **یک تبدیل برای درخواست‌های هم‌زمانِ یک نسخه**، سقف ۲ تبدیل هم‌زمان (پردازنده منبع محدود است).
- **ایمنی:** سقف پیکسل پیش از رمزگشایی (بمب فشرده‌سازی)، SVG هرگز، GIF متحرک نه، **ابرداده/EXIF/GPS در نسخه نمی‌ماند**،
  هر ناکامی همان ۴۰۴ یکنواخت.
- **نشانه‌گذاری:** `<picture>` با AVIF، سپس WebP، سپس `<img>` اصلی؛ `width`/`height` همیشه، تصویر LCP
  `eager` + `fetchpriority=high`، بقیه `lazy`.

آزمون با `sharp` واقعی و AVIF/WebP واقعی (ماژیک بایت‌ها، ابعاد، نسبت، ابرداده). یادداشت: تصویر آزمون ساختگی است؛
نسبت‌های اندازه فقط ساختاری سنجیده می‌شوند (AVIF کوچک‌تر از JPEG)، و **ادعای صرفه‌جویی برای عکس واقعی نمی‌کنیم** —
اندازه‌گیری روی عکس واقعی با داده می‌آید.
