## ۲. تصمیم‌های معماری این گام (خلاصهٔ ADR-0012)

1. **شناسهٔ نشست را صدازننده می‌دهد.** توکن مرورگر `pv1.<session_id>.<secret>`
   است؛ اگر پایگاه‌داده شناسهٔ خودش را می‌ساخت، توکن هرگز به ردیفش نمی‌رسید و
   کوکی معتبر، بی‌نام می‌شد. پس `app.complete_login(..., p_session_id)` شناسه را
   از بالا می‌گیرد و راز همچنان **پیش از درج** درهم می‌شود.
2. **CSRF فقط از هدر، نه از کوکی.** کوکی CSRF صادر می‌شود تا `fetch` هم‌مبدأ
   مقدارش را بخواند، ولی سرور آن را از کوکی **نمی‌پذیرد**؛ وگرنه مرورگر خودش
   کوکی را می‌فرستد و اثبات از بین می‌رود (آزمون واقعی: درخواست بی‌هدر ۲۰۰ گرفت).
3. **شکستِ نوشته‌دار، پاسخ برمی‌گرداند نه استثنا.** خطای بیرون‌آمده از هندلر،
   تراکنش را برمی‌گرداند؛ پس «تلاش ورود ناموفق» و «رخداد امنیتی» با آن پاک
   می‌شدند. مسیرهای ورود، خروجی `401/423` با پوشش خطای ساختاریافته می‌دهند تا
   قفل تدریجی حساب و رد حسابرسی بمانند.
4. **سقف نرخ = یک سبد برای هر مسیر.** کلید `route:<route.name>:ip:<ip>`. پیش‌تر
   کلید از نام *قاعده* ساخته می‌شد و همهٔ نوشتن‌های یک IP یک سبد داشتند: انفجار
   در یک مسیر، بقیه را می‌بست. قاعدهٔ پیش‌فرض هم به دستهٔ مسیر وابسته شد
   (`publicForm` برای بی‌نام، `writeGeneral`/`readGeneral` برای احرازشده).
5. **الگوی احراز `authenticated`.** مسیرهایی که برای انسان و ماشین یک معنا
   دارند (نمای کسب‌وکار خودمان) با این الگو، هم نشست را می‌پذیرند هم کلید API،
   و بی‌نام را با ۴۰۱ برمی‌گردانند. `business.overview` چنین مسیری است؛
   `business.get` همان نمای عمومی می‌ماند (§20: پروفایل عمومی جدا).
6. **توابع تصمیم، بولیِ سخت.** `app.is_member_of` با منطق سه‌ارزشی `NULL`
   برمی‌گرداند (وقتی زمینهٔ کلید API خالی است) و نگهبانی مثل
   `if not is_member_of(...) then raise` را **خاموش** می‌کرد: آزمون واقعی نشان داد
   غیرعضو توانست دروازهٔ انتشار را بخواند. حالا `coalesce(..., false)`.
7. **حلقهٔ تغییر مسیر، پیش از نوشتن سنجیده می‌شود.** بررسی «زنجیرهٔ موجودِ این
   مبدأ» حلقهٔ تازه را نمی‌بیند؛ `seo.would_create_loop` (مهاجرت ۰۰۱۷) از مقصد
   به عقب می‌پیماید و یالِ حلقه‌ساز را پیش از درج رد می‌کند.
8. **`select *` ممنوع.** مسیرها ستون‌ها را صریح نام می‌برند؛ تا شکست قرارداد در
   زمان مهاجرت دیده شود، نه در تولید (§58).
9. **پارامترهای SQL تایپ‌دار.** `1::smallint`، `$5::text[]`، `$6::timestamptz`:
   پارامتر بی‌نوع، حل ابهام تابع را می‌شکند (`function does not exist`) — خطایی
   که فقط در اجرای واقعی دیده می‌شود.

## ۳. سطوح دسترسی و رازها

- `pv_public` فقط `begin_login`/`complete_login`/`begin_registration`/`complete_registration`/`resolve_session`/`ops.readiness_snapshot`.
- `/ready` عددها را از تابع باریک `ops.readiness_snapshot` می‌گیرد (مهاجرت ۰۰۱۶)؛
  جدول‌های `ops.migration`/`ops.feature` همچنان به نقش بی‌نام هیچ گرنتی ندارند.
- کلید API: هش با قالب مشترک رازها (`sha256:<64hex>`)، دامنهٔ مجوز سنجیده‌شده با
  `auth.permission` پیش از ساخت، بدون هیچ نقشی، فقط کسب‌وکار خودش.
- مسیر عمومی `POST /api/v1/public/security-events`: واژگان سطح مرورگر
  (`info|warning|critical`) به واژگان پایگاه‌داده نگاشت می‌شود؛ رخداد سمت مرورگر
  «ادعا» است و مبنای تصمیم امنیتی نمی‌شود.

## ۵. چند نکتهٔ ابزاری (برای گام‌های بعد)

- `npm run build` حالا `tsc -b --force` است: بدون آن، حذف فایل‌های `dist` با
  کش `tsbuildinfo` ترکیب می‌شد و `tsc` خروجی تولید نمی‌کرد (خرابی گمراه‌کنندهٔ
  `ERR_MODULE_NOT_FOUND` در تست).
- `npm run status` تعداد تست‌ها را به تفکیک پرونده می‌دهد.
