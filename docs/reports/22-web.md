# گام ۲۲ — `apps/web` (SSR، CSP، دارایی محتوامحور، فونت)

مرجع: §45–۴۷، §64–۸۲، §93–۹۹ · Addendum §۴–۳۳، §۸۷–۸۸، §۹۱

این گام، پنجرهٔ عمومی پلتفرم را می‌سازد: سروری که صفحهٔ SEO-دار، سریع و
دسترس‌پذیر تولید می‌کند — بدون هیچ فریم‌ورک بیرونی. «بدون فریم‌ورک» اینجا
سلیقه نیست؛ نتیجهٔ یک تحلیل هزینه است: چهار چیز باید مطلقاً در دست ما باشد و
هر چهار، در فریم‌ورک «افزونه» می‌شوند: هدرهای امنیتی، سیاست کش، فشرده‌سازی، و
سقف زمان اتصال. در عوض، چیزی که از فریم‌ورک می‌گرفتیم (روتینگ و رندر) در
`router.ts` و `render.ts` سه صفحه‌ای می‌شود.

## قطعات

| فایل | کار | تصمیم کلیدی |
| --- | --- | --- |
| `src/html.ts` | ساخت رشتهٔ HTML، بی‌امکان‌کردن تزریق | سه سازنده (`escapeText`/`escapeAttr`/`attrs`) + فهرست ویژگی‌های ممنوع (`style`, `on*`) که **خطا** می‌دهند |
| `src/assets.ts` | دارایی محتوامحور | نشانی = `نام.۸نویسهٔ‌درهم.پسوند`؛ درهم یک بار در راه‌اندازی |
| `src/fonts.ts` | فونت متغیر زیرمجموعه + CLS صفر | یک فایل WOFF2 `wght 100–900`، یک `preload`، جانشین متریک‌جبران‌شده |
| `src/tokens.ts` | توکن‌های `design.token` → متغیر CSS | هر مقدار پیش از چاپ در برابر شکل مجاز **نوعش** سنجیده می‌شود |
| `src/theme.ts` | تم روشن/تاریک/پرکنتراست در یک کوئری | تاریک داخل `@media`، انتخاب کاربر بالا‌تر از آن |
| `src/styles.ts` | پوستهٔ CSS | منطقی (`margin-inline-start`)، موبایل‌اول، شکست‌ها برابر توکن `breakpoint.*` |
| `src/headers.ts` | CSP و هدرهای امنیتی | `style-src 'self'` بدون `unsafe-inline` (چون هیچ استایل درون‌خطی نداریم) |
| `src/router.ts` | جدول تصمیم مسیر/میزبان | نامک پیش از کوئری اعتبارسنجی می‌شود؛ `404` برای همهٔ حالت‌های «نیست/ندارد» |
| `src/config.ts` | پنج میزبان، یک برنامه | میزبان ناشناس ⇒ `421` بدون بازتاب `Host` |
| `src/data.ts` | کوئری‌های بی‌نام در نقش `pv_public` | ستون‌های صریح، پارامتر ایمن، افت صادقانه با `cause` در لاگ |
| `src/pages/*` | اصلی، فهرست، پروفایل، محتوا، سیستمی، خوراک‌ها | |
| `src/server.ts` | HTTP، ETag، brotli/gzip، لاگ | ترتیب ثابت: متد ⇒ مسیر ⇒ میزبان ⇒ ریدایرکت ⇒ مسیر ⇒ پاسخ ⇒ ۳۰۴ ⇒ فشرده‌سازی |

## تصمیم‌ها و دلیلشان

1. **هیچ استایلی درون‌خطی نیست.** همهٔ ظاهر از توکن‌های پایگاه‌داده می‌آید و به
   یک فایل CSS با درهم محتوا تبدیل می‌شود. تنها راه ممکن CSP سخت
   (`style-src 'self'` بدون `unsafe-inline`) همین است. آزمون، نبود `style="` را
   در خروجی می‌سنجد.
2. **فقط یک رنگ خام در کل CSS باقی می‌ماند** و آن هم داخل بلوک `@media print`
   است (چاپ باید صرف‌نظر از تم سیاه‌وسفید بماند). آزمون، همین استثنا را
   صریح نگه می‌دارد.
3. **دارایی، محتوامحور است، پس نسخه‌بندی حالت نیست.** کسی نمی‌تواند یادش برود
   نسخه را بالا ببرد؛ تغییر محتوا، نشانی را عوض می‌کند.
4. **صفحهٔ فهرست با نشانگر صفحه‌بندی می‌شود.** صفحهٔ دوم `noindex, follow` و
   بدون کانونیکال — همان توصیهٔ گوگل؛ محتوا نمایه می‌شود، نشانی نشانگری نه.
5. **افت صادقانه، نه صفحهٔ جعلی.** نبود داده ⇒ بخش حذف می‌شود یا پشتهٔ جانشین
   می‌آید؛ در لاگ می‌گوییم. هیچ عدد یا متنی جای دادهٔ واقعی نمی‌نشیند (§102، §181).
6. **میزبان ناشناس هیچ‌چیز نمی‌گیرد.** نه صفحه، نه ریدایرکت (بازتاب `Host` خودش
   یک آسیب‌پذیری کلاسیک است).
7. **مسیرهای سطح مدیریتی، `404` می‌دهند نه `403`.** `403` یعنی «هستی ولی اجازه
   نداری» و وجود سطح مدیریتی را لو می‌دهد.
8. **مجوزهای `seo.settings` داده‌محورند.** تا ایندکس روشن نشده، robots کل سایت
   را می‌بندد؛ این «توقف اضطراری» است و پیش از هر قاعدهٔ دیگری اثر می‌کند.

## چیزهایی که در همین گام «گرفته» شدند

- `m.robots` و `m.og_*` ستون‌هایی بودند که در `seo.metadata` **وجود ندارند**؛
  علت در لاگ ماسک می‌شد (`mapDatabaseError`). حالا `degrade` علت خام را هم
  لاگ می‌کند — این، عیب‌یابی را از یک بن‌بست بیرون آورد.
- `isPathAllowed` برای سایت عمومی، پیشوند `'/'` را «همهٔ مسیرها» تفسیر می‌کند؛
  تفسیر قبلی («فقط ریشه») هر مسیر تازه‌ای را پیش‌فرض می‌بست.
- میزبان بدون پورت مقایسه می‌شود: `panel.localhost:3000` در توسعه و
  `panel.petavu.ir` در تولید، یک سایت‌اند.
- الگوی توکن سایه، شکل واقعی `design.token` را پذیرفت (آرایهٔ لایه‌ها، ۲ تا ۴
  طول + رنگ).
