# ADR-0021 — کنسول مدیریت و احراز دوباره

تاریخ ۲۰۲۶-۱۰-۰۴؛ وضعیت پذیرفته؛ §10، §14–17، §24، §28، §56، §132.

منوی ۲۸‌موردی از DB می‌آید. در پایان گام ۲۹، ۱۹ بخش روی API واقعی متصل‌اند؛ ۹ بخش طبق ترتیب نقشهٔ راه در گام‌های ۳۰–۳۶ فعال می‌شوند، نه با Backend ساختگی. سطح مدیریت SSR مستقل، بدون کش/ایندکس، با توکن‌ها و چیدمان تیره است. کاربر عضو با وجود نشست به این میزبان دسترسی ندارد.

API مدیریت ستون‌ها و resourceهای بسته دارد؛ انتخاب نام جدول/SQL از درخواست یا تنظیمات ممنوع است. صفحه‌بندی با cursor پایدار و سقف ۱۰۰ انجام می‌شود. کاربران و ماتریس نقش از definerهای محدود می‌آیند: هیچ شناسهٔ ورود، هش اعتبارنامه، توکن نشست یا راز به مرورگر نمی‌رود.

تغییر وضعیت کاربر/کسب‌وکار/محتوا در تابع تراکنشی، با مجوز ریزدانه، نسخهٔ مورد انتظار، تأیید هویت در ۱۵ دقیقهٔ اخیر، گذر مجاز، Audit و Outbox انجام می‌شود. تعلیق کاربر نشست‌هایش را می‌بندد؛ خودتعلیقی ممنوع است. `/auth/reauth` رمز را با Argon2id واقعی بررسی می‌کند؛ hash فقط بین DB و API است و پاسخ صرفاً boolean است. تکمیل MFA/WebAuthn و دفاع جامع کنش‌های حساس در گام کیفیت امنیتی انجام می‌شود.

افزودن نوع کسب‌وکار بلافاصله در API عمومی دیده می‌شود. تغییر مسیر سراسری از نگهبان حلقهٔ موجود استفاده می‌کند؛ تنظیمات موجود غیرراز به‌صورت نسخه‌دار ویرایش می‌شوند. سیاست نگهداشت با soft delete برابر نیست؛ اجراکنندهٔ نگهداشت/بکاپ در گام‌های کارگر/بازیابی می‌آید.

آزمون گام: ۴۷ آزمون جدید مدیریت (همه سبز)، به‌اضافه ۱۲۸ آزمون regression API/coverage/member. آخرین اجرای کامل تا گام ۲۸: ۹۹۸/۹۹۸؛ این اعداد عمداً یکی تلقی نمی‌شوند.
