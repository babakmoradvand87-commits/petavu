# ADR-0007 — رجیستری فیچر، بودجهٔ عددی، دروازهٔ انتشار

- **تاریخ:** ۲۰۲۶-۱۰-۰۲
- **وضعیت:** پذیرفته‌شده
- **مرجع:** Addendum §1–۴، §21–24، §26–34، §96، §100، §103

## ۱. فیچر، یک ردیف است نه یک پوشه

هر امکان پلتفرم در `ops.feature` ثبت می‌شود: وضعیت چرخهٔ عمر، وابستگی‌ها، بودجهٔ
عملکرد و فراداده‌های سئو/جست‌وجو. «فیچر» در کد بدون ردیف متناظر، طبق §100 مجاز
نیست — چون هیچ فیچری جزیره نیست و هر فیچر باید به DB/API/UI/مجوز/جست‌وجو/سئو/
داده ساخت‌یافته/سایتمپ/اعلان/خودکارسازی/حسابرسی/تحلیل/عملکرد وصل باشد.

## ۲. بودجهٔ عملکرد، عدد است نه توصیه

`ops.page_budget` برای هر الگوی مسیر، سقف LCP/INP/CLS/TTFB/وزن/تعداد درخواست و
p95 API دارد. سه رأی ممکن است: `pass`، `fail` (با فهرست دقیق تخطی‌ها)، و
`unbudgeted`. **حالت سوم مهم‌ترین است:** مسیری که بودجه ندارد، سالم نیست؛
اندازه‌گیری‌نشده است.

درس فنی این گام: تابعی که یک نوع مرکب برمی‌گرداند و ردیفی پیدا نمی‌کند، «ردیف
تهی» می‌دهد نه «هیچ». اگر این را «پیدا شد» بخوانی، مسیر بی‌بودجه رأی `pass`
می‌گیرد. توابع بازگردانندهٔ جدول باید `setof` باشند.

## ۳. دروازهٔ انتشار، یک تابع است نه یک چک‌لیست انسانی

`ops.publish_gate(business_id)` چهار دروازه را می‌سنجد و با شدت گزارش می‌کند:
ساختار طراحی (بازدارنده، از `design.validate_tree`)، فرادادهٔ سئوی محتوای
منتشرشده (بازدارنده)، بودجهٔ عملکرد (اطلاع)، رجیستری فیچر (هشدار). شدت‌ها عمداً
یکسان نیستند: نبود متادیتای سئو روی صفحهٔ منتشرشده، صفحه را از دید موتور جست‌وجو
نامرئی می‌کند؛ نبود بودجه، ریسک است نه خرابی.

خط لولهٔ انتشار (Addendum: CHANGE→…→PUBLISH→MONITOR→AUDIT) در گام‌های ۳۰ و ۲۰
همین تابع را صدا می‌زند، نه یک بازنویسی از قاعده.

## ۴. صفر یعنی «بیرون از دامنه»

`rum_sample_rate = 0` مجاز است و معنی «بدون نمونه‌گیری» دارد. مسیرهای احراز
هویت صفرند: نشانی این صفحه‌ها می‌تواند توکن یک‌بارمصرف داشته باشد و RUM روی آن،
خودش نشت است. بودجه‌شان باطل نمی‌شود؛ فقط از سنجش میدانی کنار گذاشته می‌شود.
