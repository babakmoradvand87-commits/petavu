# آماده‌سازی برای انتشار روی مخزن گیت‌هاب

مخزن فعلاً **بدون remote** است: نه آدرسی ست شده و نه توکنی ذخیره شده (توکن‌ها
هیچ‌وقت داخل مخزن یا فایل نمی‌نشینند — §79).

## کاری که لازم است (یک‌بار)

آدرس مخزن را بده. اگر مخزن خالی است، گزینهٔ درست این است که ریشهٔ موجود بالا
برود، نه یک تاریخ تازه. من این‌ها را اجرا می‌کنم:

```bash
git remote add origin https://github.com/<owner>/<repo>.git
git branch -M main                  # شاخهٔ اصلی، مطابق پیش‌فرض گیت‌هاب
git push -u origin main             # همهٔ کامیت‌ها با تاریخ کامل
```

## توکن دسترسی — نکتهٔ درست از نظر امنیت

اگر توکن را در متن چت بفرستی، آن توکن برای همیشه در تاریخ مکالمه می‌ماند. دو
راه بی‌خطرتر:

۱. **توکن یک‌بارمصرف با کمترین دسترسی** (پیشنهاد من): یک Fine-grained token
   فقط برای همان یک مخزن، فقط با دسترسی `Contents: write` و مثلاً ۲۴ ساعت
   اعتبار. کار را انجام می‌دهم، و تو در گیت‌هاب توکن را همان‌جا Revoke می‌کنی.
۲. **بدون توکن، با مخزن محلی:** آدرس مخزن را بده، من `origin` را ست می‌کنم و
   همه‌چیز را آماده و کامیت می‌کنم. push را خودت از ماشین خودت با
   `git push` (یا `gh auth login`) انجام می‌دهی.

## نکتهٔ فنی: چطور توکن را به‌کار می‌برم (بدون ماندن در تاریخ)

توکن را هنگام push فقط در محیط همان یک دستور می‌گذارم و هیچ‌وقت در
`.git/config` نمی‌نویسم:

```bash
git push https://x-access-token:"$TOKEN"@github.com/<owner>/<repo>.git main
```

`git remote` بدون توکن می‌ماند، و `credential.helper store` هم استفاده نمی‌شود؛
یعنی چیزی روی دیسک نمی‌ماند که بعداً لو برود.

## از آن پس

هر گام که تمام شد، کامیت + push. اگر مخزن فقط یک **آینه** باشد و منبع حقیقت
همین ریشهٔ کاری بماند، آن‌وقت §83 هم برقرار می‌شود: اجرای پروژه هیچ‌وقت به
گیت‌هاب وابسته نیست.
