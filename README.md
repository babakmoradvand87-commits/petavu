# PETAVU

شبکهٔ کسب‌وکار صنف حیوانات خانگی و اسب.

PETAVU یک سایت تبلیغاتی نیست؛ یک سامانهٔ B2B است: کسب‌وکارها (کلینیک، پت‌شاپ،
دکتر، آموزشگاه، دامداری، باشگاه سوارکاری و…) در آن پروفایل می‌سازند، خدمات و
محصولاتشان را معرفی می‌کنند، با هم ارتباط می‌گیرند، و صفحهٔ عمومی اختصاصی
می‌گیرند — همه روی یک زیرساخت واحد که سئو، عملکرد، امنیت و خودکارسازی در آن
از ابتدا در معماری نشسته است، نه اینکه بعداً سوار شود.

## وضعیت فعلی

فاز ۰ و ۱ کامل شده‌اند:

| فاز | محتوا | وضعیت |
| --- | --- | --- |
| ۰ | ریشهٔ تمیز، اسناد حاکم، ابزار کار و قاعده‌ها | کامل |
| ۱ | `@petavu/shared` (خطا، پیکربندی، شناسه، لاگ، متن فارسی) و `@petavu/security` (Argon2id، توکن، کوکی، CSRF، محدودیت نرخ) | کامل |
| ۲ | اسکیمای پایگاه‌داده، مهاجرت‌ها، دامنه و قاعده‌های دسترسی | در جریان |
| ۳–۶ | لایهٔ داده، API، سایت، پنل‌ها، استودیو، فروشگاه، عملیات | پیشِ رو |

۹۷ تست خودکار روی پکیج‌های فاز ۱ سبز است.

## راه‌اندازی

نیازمندی: Node.js نسخهٔ ۲۰٫۱۱ یا بالاتر.

```bash
npm install        # نصب وابستگی‌ها
npm run build      # ساخت همهٔ پکیج‌ها (tsc -b)
npm test           # اجرای تست‌ها (node --test)
npm run typecheck  # بازبینی نوع‌ها از صفر
```

پیکربندی: `.env.example` را به `.env` کپی کنید. در محیط توسعه، همهٔ مقادیر
پیش‌فرض کافی‌اند و هیچ سرویس بیرونی لازم نیست — پایگاه‌دادهٔ تعبیه‌شدهٔ توسعه
بدون نصب PostgreSQL کار می‌کند.

## ساختار مخزن

```
docs/spec/         اسناد حاکم (معماری و ضمیمهٔ عملکرد/سئو/خودکارسازی/No-Code)
docs/adr/          تصمیم‌های معماری، با دلیل و پیامد
docs/engineering/  قاعده‌های کدنویسی و کار روزمره
packages/shared/   بنیاد مشترک: خطا، پیکربندی، شناسه، زمان، لاگ، متن فارسی
packages/security/ رمز عبور، نشست، توکن، کوکی، CSRF، محدودیت نرخ
tests/             تست‌های سرتاسری روی خروجی ساخته‌شده
ROADMAP.md         گام‌های اجرا، فاز به فاز
```

پکیج‌های بعدی — `db`، `domain`، `storage`، `seo`، `design-system`، `ui` — و
برنامه‌های `web`، `api`، `worker`، `panel`، `adminpanel`، `shop`، `adminshop`
در همین مخزن و با همین قاعده‌ها ساخته می‌شوند.

## آنچه این پروژه بر آن ساخته شده

۱. **امنیت از ابتدا.** نه به‌عنوان لایهٔ آخر: هر تصمیم داده و API از پرسش
   «اگر این لو برود چه می‌شود؟» شروع می‌شود.
۲. **یکپارچگی داده.** موجودیت‌ها، مالکیت، مجوز و حسابرسی در پایگاه‌داده
   تحمیل می‌شوند، نه در کد کلاینت.
۳. **معماری درست.** هیچ سیستم موازی و هیچ راه‌حل موقتی؛ هر چیزی که ساخته
   می‌شود، به الگوی موجود وصل می‌شود.
۴. **عملکرد و سئو از روز اول.** بودجهٔ عملکرد و مدل دادهٔ سئو بخشی از اسکیما
   هستند، نه یک بازبینی بعدی.
۵. **صداقت.** هیچ Mock و دادهٔ ساختگی به‌جای پیاده‌سازی نمی‌نشیند؛ هر سرویس
   یا واقعی است یا غایب و به‌صراحت غایب گزارش می‌شود.

جزئیات در `docs/spec/00-readme.md` آمده است، همراه با ترتیب داوری در تعارض:
امنیت ← یکپارچگی داده ← معماری ← عملکرد ← سئو ← خودکارسازی ← نگهداشت‌پذیری.
